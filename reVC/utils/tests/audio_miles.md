# Miles backend compiled as C11

The complete `src/audio/sampman_miles.c` translation unit is C11. It uses C SDK headers and COM calls, retains the Miles WINAPI callback signatures and 32-bit integer handles, and calls the shared `AudioSampleHost.h` for game state. The small C++ adapter now supports both OpenAL and Miles. Provider changes still go through `AudioManager`; CD wait/quit decisions stay in the frontend; CD audio restoration still changes music volume, effects volume and then services audio in that order. Direct CITA allocation sites remain in the backend.

Run `powershell -ExecutionPolicy Bypass -File utils/tests/test_audio_miles.ps1` from the repository root. The fixture extracts 18 actual state, sample metadata, provider and volume methods from the saved C++ source and current C source. It sweeps all byte volumes, channel playback states, both initialization gates, all stream slots, effects/music scaling, user-track boost, interruption state, closed streams and signed pan storage. It compares every sample slot and bank boundary and verifies borrowed provider names. Eight clang/GCC O0/O2 C11/C++17 comparisons pass. Native MSVC Win32 also matches the saved fixture output.

Run `powershell -ExecutionPolicy Bypass -File utils/tests/test_audio_sample_host.ps1 -HostBackend MSS` to check the actual game adapter callbacks through a mixed C/C++ link. Mock game objects verify provider selection, CD quit decisions and music/effects/service order without opening a window. Four clang/GCC configurations and native MSVC Win32 pass. The default OpenAL callback fixtures also continue to pass.

`build/audio-miles-native-c-tests/verification.json` records 120 current OpenAL/game consumer checks, whole Miles backend C11 compilation on clang/GCC Win32 and native MSVC Win32, clang default/CD-check/MASTER variants and native MSVC CD-check compilation. Compilation caught integer handles being reset using C++ NULL semantics, an absent Windows case-comparison alias, and preexisting duplicate/out-of-scope declarations in the formerly disabled CD-check branch. These now use proper C definitions and scan-local variables.

CMake/premake discover the renamed source, and the existing Visual Studio project selects C11 explicitly. All three sample-manager backends are now C sources. The Miles SDK backend retains its existing Win32 handle representation; no x64 Miles ABI support is claimed. Real Miles DLL playback, physical CD behavior and a full linked game build remain unverified. No GUI tests ran.
